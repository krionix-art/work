## 1. Цель

Сделать анимированный ролик «история создания Telegram-бота обновление за обновлением» на HyperFrames (HTML → MP4).
Источник фактов: файл `DEPLOYS.md` («История деплоев») в репозитории бота. Каждая запись там: дата, короткий хеш коммита, описание. Новые записи сверху.

Ролик: **хроника деплоев от июля до 1 октября 2026**, глава за главой, каждая глава = одно значимое обновление или связка обновлений.

## 6. Дизайн-система (согласована в предыдущей сессии; можно менять с обоснованием)

**Концепт:** журнал деплоев превращается в фильм. Каждая запись журнала — глава с датой, хешем коммита (моно-шрифт) и одной наглядной сценкой справа.

**Палитра** (одна акцентная, остальные цвета только по смыслу):
- фон `#0b0e13`, панели `#141922` и `#1b212c`, линии `#262e3b`
- текст `#f1ece2` (тёплая бумага), приглушённый текст `#8d99ad`
- акцент: янтарь `#ffb347`
- семантика: успех `#7fd49b`, ошибка/инцидент `#ff6b5e`
- избегай шаблонных ИИ-приёмов: градиентный текст, чистые `#000`/`#fff`, левые акцентные полоски, одинаковые карточки в сетке

**Шрифты:** Montserrat 800/900 — заголовки; Montserrat 500/700 — основной текст; JetBrains Mono — даты, хеши, числа, код; Cormorant Garamond — только в сцене «цитаты-картинки» (так выглядит настоящая цитата бота).
Размеры для просмотра на весь экран: заголовок от 72 px, основной текст от 32 px, подписи не мельче 20 px. Межбуквенный интервал у крупных заголовков −0.03em.

**Сетка кадра:** поля 120 px. Левая колонка (x 120–900): дата + хеш, заголовок, одна строка пояснения. Правая колонка (x 1000–1800, около 780×680): визуал главы. Полоса прогресса внизу (y ≈ 960–1040).

**Постоянный слой (в корне, поверх сцен):**
- нижняя шкала «ИЮЛ — АВГ — СЕН — ОКТ» с точками по главам, растущей линией и подсветкой текущей главы;
- счётчик «04 / 16» в углу;
- фон: еле заметная сетка точек, два медленных светящихся пятна, гигантское «призрачное» слово месяца с непрозрачностью 4–6%.

**Ритм:** глава ≈ 4,5 с (1 с вход, 2,5 с чтение, 0,5 с выход, перекрытие соседних сцен около 0,35 с). Вступление 5 с, финал 6 с. Не больше 14 слов в кадре на главу, всё должно читаться за 2 секунды.

**Идеи визуалов по главам** (необязательные, сценарий главнее; делай каждую сцену разной по форме):
старт — карточки «изменено / удалено» с зачёркнутым и новым текстом; подписка — полоса из 7 дней пробного периода → карточка «Месяц»; игра — поле 9×9 с крестиками и ноликами, выигранный малый квадрат подсвечивается; переезд базы — счётчик ключей 0→1115 и полоса прогресса; переезд на сервер — два узла и стрелка, «ошибок: 0»; голосовые — волна превращается в текст, две полосы «3,5 мин» и «20 с»; личка-пульт — голосовое → карточка задачи; /textme — «Ответь мне!» вспыхивает и исчезает, счётчик до 103; цитаты — чёрная карточка с портретом и антиквой; инцидент с сервером — красный терминал и чек-лист «что не потеряно»; звук TikTok — две волны (тонкая → насыщенная); «Пульт» — экран телефона с плитками; кроны — календарь с серыми днями и одним янтарным; хранилище Vercel — шкала на 100% и фраза про `docs/`; оплата звёздами — три кнопки; оплата рублями — одно сообщение, которое меняет содержимое по шагам.

## 7. Технические правила HyperFrames (коротко; детали в навыках `hyperframes-core` и `hyperframes-animation`)

Обязательно прочитай перед написанием HTML: `hyperframes-core/SKILL.md` и `references/determinism-rules.md`, `hyperframes-creative/references/house-style.md`, `video-composition.md`, `hyperframes-animation` (правила и переходы).

1. Корень: `<div id="root" data-composition-id="main" data-width="1920" data-height="1080" data-duration="<сек>">`, без `<template>`. В CSS корень `width:100%; height:100%`, **не** `1920px`.
2. Каждая сцена — `class="clip"` с `data-start` и `data-duration`. Видимостью клипа управляет рантайм.
3. Одна таймлайн-инстанция: `gsap.timeline({ paused: true })`, регистрация `window.__timelines["main"] = tl` (ключ = `data-composition-id`).
4. **Нельзя:** анимировать `display`/`visibility`/`autoAlpha` у `.clip` (анимируй дочерний враппер); `repeat: -1`; `Math.random` без seed; `Date.now()`/`performance.now()`; сетевые запросы при рендере; `<br>` в тексте.
5. Не задавай начальный `transform` в CSS для того же свойства, которое анимирует GSAP (`gsap_css_transform_conflict`). Центрируй через flex/`inset`. Для входа используй `fromTo`.
6. Трансформируемые элементы должны быть блочными и иметь размер (`display:block`, `width/height`), иначе `scaleX` ничего не покажет.
7. Все `id` уникальны во всей странице (префикс сцены: `s07-title`).
8. Счётчики через `onUpdate` на объекте (`{v:0}` → `textContent`) допустимы и детерминированы при перемотке.
9. Пульсирующим декоративам оставляй запас по краям, не заходи на границу `overflow:hidden`.
10. Не прячь текст под нижнюю шкалу и за края кадра. Контраст по WCAG AA проверяет `check`.

Подход к сборке, который я планировал: один файл `index.html`, сгенерированный скриптом `build.mjs` из массива глав (общий шаблон сцены + индивидуальный HTML визуала + индивидуальная функция анимации). Это даёт единый стиль и быстрые правки. Если сцен станет больше или они тяжёлые, можно вынести их в `compositions/*.html`, тогда читай `references/sub-compositions.md` (стили и скрипты внутри `<template>`, id хоста = id внутри = ключ таймлайна).

## 8. Звук

- Сначала спроси или проверь, нужен ли звук (по умолчанию: фоновая музыка без голоса).
- Используй `/media-use` (`../media-use/references/resolve.md`). Перед первым действием с авторизацией выполни `npx hyperframes auth status` и покажи пользователю вывод как есть.
- Если каталога нет и войти нельзя: синтезируй минималистичный бит или паттерн ffmpeg-ом, либо отдай немое видео и скажи об этом. Не выдумывай лицензии на чужую музыку.
- Каждому `<audio>` нужен `id`, иначе звук не попадёт в рендер. Громкость музыки умеренная (`data-volume`), плавные `data-fade-in` / `data-fade-out`.

## 9. Контроль фактов

- Цифры, хеши и даты брать **только** из `DEPLOYS.md`. Ничего не выдумывать и не «округлять в красивую сторону».
- В записях без хеша («этот пуш», «предыдущие пуши дня», «Инфраструктура, без коммита кода») хеш не рисовать, вместо него метка вроде «без коммита».
- Отметь в ролике то, что в журнале **не проверено вживую** (например, оплата звёздами и рублями): не рассказывай как о доказанном факте.
- В конце дай пользователю список использованных фактов: глава → запись журнала (дата + хеш) → цифры, показанные в кадре.
- Не показывай секреты, токены, значения переменных окружения (в журнале их нет, но проверь, что не попало в сцены).

## 10. Порядок работы

1. Прочитать сценарий пользователя, `DEPLOYS.md` и навыки (§4, §7).
2. Задать оставшиеся вопросы: приватность (§3), звук (§8), если сценарий что-то оставил открытым.
3. Записать `BRIEF.md` и `STORYBOARD.md` (по одному блоку `## Frame N` на главу, `status: outline`). Формат: `~/.claude/skills/hyperframes/references/brief-format.md` и `storyboard-format.md`.
4. Собрать `index.html`: сначала статичные состояния «в конце сцены», потом анимация.
5. Проверки по ходу работы:
   - `npx hyperframes lint` после первого прохода;
   - `npx hyperframes check` как итоговый шлюз (lint + runtime + layout + контраст). Число «0 samples» после lint-ошибки значит, что проверки не запускались, а не «всё хорошо»;
   - `npx hyperframes snapshot --at <секунды>` по середине каждой главы, смотреть PNG глазами (Read);
   - `npx hyperframes timeline` для списка клипов.
6. Показать превью (`npx hyperframes preview --background`) и спросить пользователя про рендер или правки.
7. Рендер после согласия: `npx hyperframes render -f 30 -q standard -o out/bot-history.mp4`. После рендера прочитать вторую строку итога (режим захвата, GPU, стадии), проверить файл через `ffprobe` (длительность, размер кадра 1920×1080, наличие звука, если он есть) и посмотреть несколько кадров.
8. Если рендер идёт медленно (режим `screenshot` + программный GPU), для черновиков используй `-q draft`, а для финала `--workers 4`.
